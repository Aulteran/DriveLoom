# ADR 0001: Platform foundations for milestone 1.1

Status: proposed. Owner review before 1.2 starts.

## Decisions

- **Language and runtime:** TypeScript (owner decision, 2026-11-11) on Node 22, matching the existing toolchain. Strict mode with erasable syntax only (no enums or parameter properties), so Node 22 runs `.ts` directly through built-in type stripping with no build step. `tsc` type-checks only (`noEmit`) and runs in `npm run check`. Branded `Id` and `Decimal` types guard against unvalidated ids and JS numbers for exact values. The web client is expected to share the language; types generated from the OpenAPI file are a later decision.
- **Database:** PostgreSQL 16, via Docker Compose, using the `pg` driver. Integration tests run against a real PostgreSQL, per the verification plan.
- **Contract:** OpenAPI 3.1 in YAML, validated in CI with `@seriousme/openapi-schema-validator`.
- **Identifiers:** UUIDv7 generated by the application. PostgreSQL 16 has no native generator, and app-side ids keep import/restore and cross-instance work simple.
- **Migrations:** in-repo forward-only SQL runner (about 60 lines) rather than a framework, so ownership and checksums are explicit. Revisit if migration needs outgrow it.
- **Tests:** `node:test` running TypeScript directly, no extra framework.
- **Dependencies:** `pg`, plus `typescript`, `@types/node`, `@types/pg`, `yaml` and the OpenAPI validator as dev dependencies. All are permissively licensed and compatible with AGPL-3.0-only.

## Deferred

HTTP framework, auth libraries, decimal and CSV libraries, image storage and web framework are chosen in the milestones that need them.
